## 1. MVP 目标

**一句话**：心理赛道，输入点子 → AI 判断+生产 → 你审核 → 手动发布。跑通整条链。

```
你输入一个想法
    │
    ▼
AI 告诉你值不值得做（搜索竞品 + 打分）
    │
    ▼  你点「通过」
AI 生成公众号长文 + 小红书短文 + 视频脚本（三选一或全要）
    │
    ▼  你审核内容，编辑、确认
完成。复制到各平台发布。
```

**不做的事**：
- 不做自动发布（手动复制粘贴）
- 不做数据看板（发布了就是你的事）
- 不做定时任务、热点监控、多赛道
- 不做视频合成（只给你脚本，剪映自己搞定）

**验证什么**：
- AI 写的内容，质量过不过你的标准？
- 整个流程从点子到成品，顺不顺？
- 你每天实际需要多少时间审核？

## 2. 砍掉的东西（有意识不做）

| 蓝图里的东西 | MVP 的做法 | 理由 |
|---|---|---|
| PostgreSQL | **SQLite** | 单机单用户，SQLite 绰绰有余。SQLAlchemy 抽象层，后续改一行配置切 PG |
| Docker | **裸跑 Python + Node** | MVP 先不搞容器，`pip install` + `npm install` 直接跑。Phase 1 末期再加 |
| 7 个 Agent | **3 个**（价值判断 + 内容生产 + 标题优化） | 路由、素材搜索、热点、策略...现阶段用不上 |
| 4 道门禁 | **2 道**（价值判断 + 内容审核） | 平台路由和发布时间发布确认，你自己在审核时决定 |
| 8 个前端页面 | **2 个**（首页+流水线 / 审核队列） | 其他页面先放占位链接 |
| WebSocket | **普通 HTTP 刷新** | 一个人用，刷新页面 < 1 秒 |
| 多赛道架构 | **硬编码「心理」赛道** | 等心理学跑通了再加配置化 |
| 视频合成 FFmpeg | **只出脚本 + TTS 语音** | 视频剪辑用剪映，不需要服务器合成 |
| Alembic 数据库迁移 | **SQLAlchemy create_all** | SQLite 文件就是数据库，备份=复制文件 |
| Nginx | **直接访问 FastAPI 端口** | 开发阶段不需要反向代理 |

## 4. 核心流程

```
┌───────────┐
│ 1. 输入点子 │  你在页面上输入一句话，比如「原生家庭对亲密关系的影响」
└─────┬─────┘
      ▼
┌──────────────────┐
│ 🔴 门禁 1：价值判断 │  AI 搜索同主题内容 → 评估差异化空间 → 给 0-10 分 + 建议
│                  │  → ≥5 分：推荐做 → 你决定做不做
│ 产出：评分+理由   │  → <5 分：建议放弃 → 你也可以坚持做
└─────┬────────────┘
      ▼  你点「通过，开始生产」
┌──────────────────┐
│   2. 内容生产      │  并行生成（你勾选要哪些）：
│                  │  ├── 公众号长文（1500-2000 字）
│                  │  ├── 小红书短文（300-500 字）
│                  │  └── 视频脚本（3 分钟口播稿）
│ 产出：文案/脚本    │  ＋ 标题建议
└─────┬────────────┘
      ▼
┌──────────────────┐
│ 🔴 门禁 2：内容审核 │  逐条预览、编辑、确认。
│                  │  → 不满意某条 → 单独重做那条
│ 产出：定稿内容     │  → 满意 → 标记完成
└─────┬────────────┘
      ▼
┌──────────────────┐
│   3. 发布         │  把内容复制到各平台发布。
│                  │  在系统里点「已发布」，记录一下链接。
└──────────────────┘
```

## 5. 数据库（2 张表）

### content_items（内容条目）

整个流程的核心表，一条记录 = 一个点子从生到死的全部信息。

```sql
CREATE TABLE content_items (
    id            TEXT PRIMARY KEY,          -- UUID
    idea_text     TEXT NOT NULL,             -- 原始点子
    track         TEXT DEFAULT 'psychology', -- 暂时只有心理
    status        TEXT DEFAULT 'draft',      -- draft→pending_review→approved→in_production→completed→rejected

    -- 门禁 1
    gate1_score   INTEGER,                   -- 0-10
    gate1_reason  TEXT,                      -- AI 给出的理由
    gate1_passed  INTEGER DEFAULT 0,         -- 0 还是 1（你点的）

    -- 门禁 2（内容审核）
    content_gzh   TEXT,                      -- 公众号长文
    content_xhs   TEXT,                      -- 小红书短文
    content_video_script TEXT,               -- 视频脚本
    title_suggestions  TEXT,                 -- JSON: ["标题1", "标题2", "标题3"]

    -- 你的操作
    selected_types TEXT,                     -- JSON: ["gzh", "xhs", "video"] —— 你勾选了哪些
    final_content TEXT,                      -- 你编辑后的定稿（JSON）
    publish_url   TEXT,                      -- 发布后的链接（手动填）
    notes         TEXT,                      -- 你的备注

    created_at    TEXT DEFAULT (datetime('now')),
    updated_at    TEXT DEFAULT (datetime('now'))
);
```

### quality_logs（质量日志，可选）

```sql
CREATE TABLE quality_logs (
    id            TEXT PRIMARY KEY,
    content_item_id TEXT REFERENCES content_items(id),
    step          TEXT,                      -- gate1 / production / review
    model         TEXT,                      -- 用了哪个模型
    tokens_in     INTEGER,
    tokens_out    INTEGER,
    latency_ms    INTEGER,
    you_edited    INTEGER DEFAULT 0,         -- 你是否手动改过 AI 输出（1=改了）
    satisfaction  INTEGER,                   -- 1-5 你对这次输出的满意度（未来可填）
    created_at    TEXT DEFAULT (datetime('now'))
);
```

> **为什么留 quality_logs？** 这是你迭代的根据——哪些步骤你每次都要改、哪些模型效果好。比事后回忆靠谱。

## 6. API（精简版）

```
POST   /api/ideas                          # 提交新点子 → 触发门禁 1
GET    /api/ideas/{id}                     # 查看点子详情（含门禁结果 + 生产内容）

POST   /api/ideas/{id}/gate1/approve       # 通过门禁 1
POST   /api/ideas/{id}/gate1/reject        # 驳回

POST   /api/ideas/{id}/produce             # 开始生产（body: 勾选哪些类型）
GET    /api/ideas/{id}/produce/status      # 查生产进度

POST   /api/ideas/{id}/review/approve      # 审核通过（门禁 2）
POST   /api/ideas/{id}/review/reject       # 退回重做某条
PATCH  /api/ideas/{id}/review/edit         # 编辑内容

POST   /api/ideas/{id}/publish             # 标记已发布（body: publish_url）

GET    /api/ideas                          # 点子列表（?status=xxx 筛选）
GET    /api/queue/review                   # 审核队列（status=completed 的条目）
```

**15 个端点，不难。**

## 8. Agent（3 个）

### Agent 1：价值判断

```
角色：你是自媒体内容价值评估专家。

输入：用户的一个内容点子（一句话）

步骤：
1. 调用搜索 API，查有没有同类内容
2. 分析差异化空间
3. 给出 0-10 分 + 一句话理由 + 建议

输出格式（JSON）：
{
  "score": 7,
  "competitor_count": 15,
  "summary": "已有 15 篇类似内容，但依恋理论角度鲜有人做",
  "suggestion": "做",
  "angle_suggestion": "建议从「童年依恋如何影响成年后的亲密关系模式」切入"
}
```

### Agent 2：内容生产

```
角色：你是心理学领域的专业内容写手。

输入：点子 + 价值判断结果 + 你要生产的类型（gzh/xhs/video）

输出（JSON）：
{
  "gzh_article": {
    "title": "...",
    "content": "公众号长文全文，1500-2000 字..."
  },
  "xhs_note": {
    "title": "...",
    "content": "小红书短文，300-500 字，加 emoji..."
  },
  "video_script": {
    "title": "...",
    "script": "3 分钟口播稿...",
    "duration_estimate": "约 180 秒"
  }
}
```

**关键**：一次 API 调用同时生成所有勾选的类型，省 token。不改动 prompt 结构，只变化 content 部分。

### Agent 3：标题优化（可选，审核时用）

```
如果审核时你觉得标题不好，点「优化标题」，这个 Agent 给 3 个备选标题。
不单独作为一个流程步骤，而是审核时的辅助功能。
```

## 9. 实施步骤

### Phase 0：环境验证（0.5 天）

```
目标：确认服务器跑得动，API 能调通
```

| 步骤 | 做什么 | 怎么验证 |
|------|--------|----------|
| 0.1 | 创建 GitHub repo `omnipost` | `gh repo create` |
| 0.2 | 初始化后端项目 | `uvicorn main:app` 跑通，能看到 /docs |
| 0.3 | 初始化前端项目 | `npm run dev` 跑通，能看到 Vite 默认页 |
| 0.4 | Claude API 调通 | 发一条请求，收到正常回复 |
| 0.5 | 搜索 API 调通 | Tavily 搜「原生家庭 心理学」，有结果 |
| 0.6 | Edge TTS 调通（可选） | 生成一段中文语音，能播放 |

### Phase 1：最小闭环（1.5-2 周）

```
目标：输入一个点子，拿到 AI 写的内容，审核后标记完成
```

#### 第 1 周：后端核心

| 任务 | 说明 |
|---|---|
| 建表 | SQLite，2 张表（content_items + quality_logs） |
| POST /api/ideas | 接收点子 → 调价值判断 Agent → 存入 DB → 返回结果 |
| GET /api/ideas/{id} | 返回一条记录的完整状态 |
| POST /api/ideas/{id}/gate1/approve | 标记通过 |
| POST /api/ideas/{id}/produce | 调内容生产 Agent → 存入 DB |
| PATCH /api/ideas/{id}/review/edit | 编辑内容 |
| POST /api/ideas/{id}/review/approve | 标记完成 |
| POST /api/ideas/{id}/publish | 记录发布链接 |

#### 第 2 周：前端

| 任务 | 说明 |
|---|---|
| 首页 | 快速输入框 + 进行中/已完成列表 |
| 点子详情页 | 门禁 1 卡片 + 生产按钮 + 审核区 |
| 审核队列 | 待审核条目列表 |
| 预览/编辑 | 内容展示 + 可编辑文本框 |

### Phase 1.5：你自己验证（1 周，边用边改）

```
目标：用真实点子跑 5-10 轮，看质量、调 prompt、修 bug
```

**这步比开发重要。** 如果 AI 写的东西你每次都大改，说明 prompt 不对或者这个赛道不适合 AI 生成。早点验证，早点决定要不要继续。

## 11. 迁移路径（Phase 2+）

瘦身版不会限制未来。这些切换都是一行配置/一个命令：

| 从 | 到 | 怎么切 |
|---|---|---|
| SQLite | PostgreSQL | 改 `DATABASE_URL`，SQLAlchemy 自动适配 |
| 裸跑 | Docker | `docker-compose up`（蓝图已有设计） |
| 3 Agent | 7 Agent | 加 prompt 文件 + 注册流水线 |
| 2 页面 | 8 页面 | 加路由 + 组件 |
| 2 门禁 | 4 门禁 | 加 Agent + API 端点 |
| 硬编码心理 | 多赛道配置 | 加 `tracks.yaml`（蓝图已有设计） |
| 手动发布 | 自动发布 | 加平台 API 对接 |

---

> **一句话总结**：先做一条能跑的通路，验证核心假设。蓝图的完整设计是对的，只是不该一开始就全做。
